# استاندارد اجباری سئو برای تمام محتوای سایت حسین

این استاندارد برای تمام صفحات فعلی و آینده سایت، از جمله مقالات وبلاگ، هاب جامع مشهد، خوشه‌های زیارتی، صفحات خدمات و خوشه گردشگری سلامت لازم‌الاجراست. هیچ صفحه‌ای صرفاً به دلیل انتشار متن، آماده محسوب نمی‌شود. محتوای قبلی نیز باید به‌صورت مرحله‌ای ممیزی و اصلاح شود.

## 1. معیار پذیرش صفحه

- [ ] نیت جست‌وجوی اصلی و مخاطب مشخص است؛ صفحه با صفحات دیگر سایت برای یک عبارت یکسان رقابت غیرضروری ندارد.
- [ ] عنوان سئو منحصربه‌فرد، دقیق، طبیعی و متناسب با زبان عربی مخاطب است؛ عبارت اصلی نزدیک ابتدای عنوان قرار می‌گیرد و از تکرار کلمات کلیدی پرهیز می‌شود.
- [ ] یک H1 منحصربه‌فرد با عنوان و موضوع صفحه هماهنگ وجود دارد؛ ساختار H2/H3 منطقی است.
- [ ] توضیحات متا منحصربه‌فرد، توصیفی و ترغیب‌کننده است و محتوای صفحه را درست بازتاب می‌دهد؛ طول آن بر اساس نمایش واقعی در ابزار بررسی شود، نه یک حد ثابت مکانیکی.
- [ ] URL کوتاه، پایدار، قابل‌فهم و canonical آن به نشانی اصلی همان صفحه اشاره می‌کند.
- [ ] robots meta و وضعیت HTTP اجازه خزش و ایندکس موردنظر را می‌دهند؛ صفحه خطای ناخواسته یا canonical متناقض ندارد.
- [ ] Open Graph شامل `og:title`، `og:description`، `og:type`، `og:url` و `og:image` صحیح است؛ در صورت نیاز، کارت‌های Twitter/X نیز تنظیم می‌شوند.
- [ ] لینک‌های داخلی مرتبط به هاب بالادستی، صفحات هم‌خوشه و صفحات خدمات مناسب اضافه شده‌اند؛ متن لینک توصیفی است و هیچ لینک شکسته‌ای باقی نمی‌ماند.
- [ ] محتوا پاسخ کامل و اختصاصی به نیاز کاربر می‌دهد، از صفحات دیگر کپی یا با تغییر نام شهر/تخصص بازنویسی ماشینی نشده و ادعاهای اثبات‌نشده ندارد.
- [ ] تاریخ انتشار/به‌روزرسانی فقط وقتی نمایش داده می‌شود که واقعی باشد؛ تاریخ ساختگی یا به‌روزرسانی صوری ممنوع است.
- [ ] خوانایی عربی، نگارش طبیعی، RTL، موبایل، دسترس‌پذیری و CTA متناسب با هدف صفحه بررسی شده‌اند.

## 2. تصویر شاخص و سئوی کامل تصویر

هر مقاله یا صفحه محتوایی ایندکس‌پذیر باید تصویر شاخص مرتبط و مجاز داشته باشد. تصویر تزئینی عمومی جای تصویر مرتبط با موضوع را نمی‌گیرد.

- [ ] تصویر واقعی، مرتبط با موضوع و دارای حق استفاده/مجوز قابل‌بررسی است؛ برای صفحات درمانی از تصاویر گمراه‌کننده، قبل‌و‌بعد بدون مجوز یا تصویر القاکننده نتیجه تضمینی استفاده نمی‌شود.
- [ ] فایل با نام توصیفی و کوتاه لاتین ذخیره می‌شود؛ از نام‌هایی مانند `IMG_1234.jpg` یا انباشتن کلیدواژه‌ها پرهیز می‌شود.
- [ ] ترجیح با AVIF/WebP بهینه است؛ ابعاد متناسب با طراحی و تصویر اشتراک‌گذاری انتخاب می‌شود، معمولاً نسبت 1.91:1 و اندازه نزدیک 1200×630 برای OG.
- [ ] حجم تصویر تا حد امکان کاهش می‌یابد بدون افت بصری محسوس؛ از تحویل فایل‌های سنگین بی‌دلیل جلوگیری می‌شود.
- [ ] تگ `<img>` دارای `alt` دقیق و طبیعی به زبان صفحه است. متن جایگزین آنچه را واقعاً در تصویر دیده می‌شود توصیف می‌کند، نه فهرست کلمات کلیدی. برای تصویر کاملاً تزئینی `alt=""` به‌کار می‌رود.
- [ ] `width` و `height` برای کاهش CLS مشخص‌اند؛ `srcset` و `sizes` در صورت وجود نسخه‌های چنداندازه استفاده می‌شوند.
- [ ] تصویر شاخص مهم صفحه با `og:image` و `twitter:image` هماهنگ است و URL آن مطلق، معتبر، قابل دسترسی و قابل خزش است.
- [ ] برای تصویر اصلی بالای صفحه، بارگذاری و اولویت به‌درستی تنظیم می‌شود؛ تصویر LCP نباید به‌اشتباه lazy-load شود. تصاویر پایین صفحه می‌توانند lazy-load شوند.
- [ ] متن ALT، نام فایل، عنوان/کپشن در صورت نیاز و زمینه اطراف تصویر با محتوای واقعی هماهنگ‌اند.
- [ ] منبع و مجوز تصاویر بیرونی بررسی و انتساب لازم حفظ شده است. از URLهای حدسی، فایل‌های دارای واترمارک یا تصاویر بدون مجوز استفاده نمی‌شود.

## 3. داده‌های ساختاریافته (Schema.org)

- [ ] JSON-LD معتبر و بدون خطای نحوی است و با محتوای قابل‌مشاهده صفحه تطابق دارد.
- [ ] برای مقاله از نوع مناسب مانند `Article` یا `BlogPosting`، برای هاب از `CollectionPage`/`ItemList` و برای مسیر راهنما از `BreadcrumbList` استفاده می‌شود؛ نوع اسکیما باید با ماهیت واقعی صفحه مطابقت داشته باشد.
- [ ] `headline`/`name`، `description`، `url`، `mainEntityOfPage`، `inLanguage`، `image` و اطلاعات نویسنده/ناشر در صورت قابل‌اثبات بودن، درست تعریف می‌شوند.
- [ ] `datePublished` و `dateModified` فقط با تاریخ واقعی درج می‌شوند. داده‌های ساختاریافته تکراری یا متناقض حذف می‌شوند.
- [ ] FAQ schema فقط زمانی استفاده می‌شود که پرسش‌وپاسخ واقعاً روی صفحه قابل‌مشاهده باشد؛ وجود اسکیما تضمین نمایش نتیجه غنی نیست.
- [ ] برای مراکز درمانی، پزشکان، امتیازها، قیمت‌ها، آدرس‌ها و خدمات، هیچ داده‌ای جعل یا حدس زده نمی‌شود.
- [ ] صفحات پس از تغییر با Schema Markup Validator و در صورت مرتبط بودن با Google Rich Results Test بررسی می‌شوند.

## 4. سئو فنی و تجربه کاربری

- [ ] صفحه با HTTPS و پاسخ HTTP صحیح باز می‌شود؛ canonical، sitemap و لینک‌های داخلی با هم سازگارند.
- [ ] صفحه در sitemap XML فقط در صورت canonical و قابل‌ایندکس بودن حضور دارد؛ robots.txt مانع ناخواسته نیست.
- [ ] تصاویر و منابع ضروری در موبایل درست بارگذاری می‌شوند؛ اندازه‌های تصویر، CLS، LCP، وزن صفحه و جاوااسکریپت اضافی بررسی می‌شوند.
- [ ] لینک‌های شکسته، خطاهای کنسول، عنوان‌های تکراری، متاهای خالی، چند H1 ناخواسته و محتوای تکراری بررسی می‌شوند.
- [ ] صفحه در موبایل خوانا و سریع است؛ تبلیغ/CTA مانع محتوا نمی‌شود و لینک‌های تماس قابل‌استفاده‌اند.
- [ ] دسترس‌پذیری پایه، کنتراست، فوکوس، زبان صفحه، `dir="rtl"` و برچسب‌های قابل‌فهم کنترل می‌شوند.

## 5. الزامات ویژه گردشگری سلامت

- اطلاعات درمانی، نام بیمارستان‌ها، تخصص‌ها، روش‌ها و مسیر تماس باید تا حد امکان با منبع رسمی یا تأیید مستقیم بررسی شوند.
- هر صفحه باید روشن کند که موجودبودن پزشک/روش، هزینه، زمان انتظار، ویزا، پذیرش بیمار خارجی و نتیجه درمان نیازمند تأیید موردی است.
- ادعاهایی مانند «بهترین»، «تضمینی»، نرخ موفقیت، قیمت قطعی یا نتیجه پزشکی بدون منبع معتبر و تاریخ بررسی‌شده ممنوع است.
- محتوای سلامت باید اطلاعاتی و محتاطانه باشد و جایگزین ارزیابی پزشک معرفی نشود.
- صفحات تخصصی باید اطلاعات متمایز و مفید داشته باشند؛ ساخت صفحات انبوه با متن تقریباً یکسان و فقط تغییر نام تخصص/بیمارستان ممنوع است.

## 6. امتیازدهی و معیار انتشار

- هدف عملیاتی: کسب حداقل 90 از 100 در ابزار ممیزی سئو مناسب، هرجا که ابزار چنین امتیازی ارائه می‌دهد، و صفر خطای بحرانی فنی/ساختاریافته.
- امتیاز Lighthouse/PageSpeed، ابزارهای ممیزی سئو و تست schema معیارهای تشخیصی‌اند؛ هیچ‌کدام به‌تنهایی معیار قطعی کیفیت محتوا یا تضمین رتبه گوگل نیستند.
- امتیاز ابزار، نام ابزار، تاریخ آزمون، خطاها و موارد استثنا باید در گزارش ممیزی ثبت شود. امتیاز را نباید بدون اجرای واقعی ابزار ادعا کرد.
- صفحه تا زمان تکمیل عنوان سئو، متا، canonical، اسکیما، تصویر شاخص و بررسی کامل سئوی تصویر، لینک‌سازی و تست‌های مربوط، «سئو کامل» علامت نمی‌خورد.

## 7. ممیزی مطالب قبلی

مطالب موجود نیز باید با همین معیارها بررسی شوند. ابتدا صفحات مهم هاب و خوشه‌های زیارتی/گردشگری سلامت، سپس صفحات پربازدید یا نزدیک به تبدیل و در نهایت سایر صفحات. هر مورد ناقص باید در فهرست ممیزی با وضعیت مشخص شود؛ وجود متا یا اسکیما به‌تنهایی به معنی قبولی صفحه نیست.
